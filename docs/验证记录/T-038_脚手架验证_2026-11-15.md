## 3. 逐项结论、证据与影响

### 3.1 构建与 lint 可复现

**结论**：`assembleDebug` 与 `lintDebug` 均可执行成功，lint 为 `0 errors, 3 warnings`，与 `docs/任务进度.md` L158 的记录一致。

**证据**

- `assembleDebug`：首次 exit 0（600ms，36 tasks up-to-date）；`--rerun-tasks` exit 0（3s，`compileDebugKotlin`、`packageDebug` 实际执行）；APK `app/build/outputs/apk/debug/app-debug.apk`（31,953,370 B）。
- `lintDebug`：exit 0；强制 `--rerun-tasks` 后 `app/build/reports/lint-results-debug.txt` 末尾仍为 `0 errors, 3 warnings`。
- 另一产物：`app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`（2,540,605 B，16:28）、`app/build/outputs/apk/release/app-release.apk`（24,596,328 B，22:13）。

**影响**：工程可构建、lint 结果稳定。注意本次未跑 `testDebugUnitTest`（不在 8 项内，见 §5）。

### 3.2 包边界与 `di/`

**结论**：主源码包含 `ui / interaction / domain / data / platform / di` 六层加根包两个文件，与 06 目录树一致。`di/` **不属越界**：06 将其列为独立层。

**证据**

- 06 L82：目录树含 `di/AppContainer.kt  # 手工装配；唯一 new 具体实现的地方`。
- 06 L132（STR-06）：`di` 职责"手工装配具体实现"，允许依赖"全部层"，禁止"业务规则/页面逻辑"——**未禁止 Android import**；`di/AppContainer.kt` L3 仅 `import android.content.Context`，无业务代码。
- 06 L129（STR-03）：`domain` 禁止 `android.*`/`androidx.*`。实测 `grep -rn "import android\|import androidx" app/.../domain` 无输出。
- 06 L130/L131：`data`/`platform` 禁止引用 `ui`/`interaction`。实测 grep 无命中。
- 目录清单：main 下仅 `data/…`、`di`、`domain/…`、`interaction`、`platform/…`、`ui/…` 与根 `MainActivity.kt`、`NautileApp.kt`；port 5 个、替身 5 个均在位。

**影响**：包边界与 06 一致。另见 §6 的清单外新增（`res/xml/data_extraction_rules.xml`），它不改变包结构。

### 3.3 SDK 版本、wrapper 与 JDK

**结论**：`compileSdk 37 / targetSdk 36 / minSdk 31`、wrapper `9.6.0` 与 06 一致；**JDK 17 只是调用时传入的变量，仓库没有固定**，默认运行在 JDK 21。

**证据**

- `app/build.gradle.kts` L23 `compileSdk = 37`；L27 `minSdk = 31`；L28 `targetSdk = 36`。
- 06 L26（C-11）：compileSdk 37 用户确认；06 L154（VER-08）：`37 / 36 / 31`。
- `gradle/wrapper/gradle-wrapper.properties` L3 `distributionUrl=…gradle-9.6.0-bin.zip`；`~/.gradle/wrapper/dists` 含 `gradle-9.6.0-bin`。
- 06 L20（C-05）要求 JDK 17 且"不以 JDK 21 作为默认"。实测：未设 `JAVA_HOME` 时 `./gradlew --version` 显示 `Launcher JVM: 21.0.13`；`grep java.home` 在 `gradle.properties`/`settings.gradle.kts`/两个 `build.gradle.kts` 中均无配置；`JAVA_HOME=…jdk-17.0.21+9` 时构建成功。
- 守护进程日志显示同日存在两类构建：`javaHome=…jdk-17.0.21+9` 与 `javaHome=/usr/lib/jvm/java-21-openjdk-amd64`（`~/.gradle/daemon/9.6.0/daemon-*.log` 22:12 两条）。

**影响**：若换机器或未显式传 `JAVA_HOME`，实际用 JDK 21 构建；`compileOptions`/`jvmTarget` 为 17 只保证字节码目标，不等于构建用 JDK 17。属与 C-05 的差异，是否固定由用户/开发决定，本次未改。

### 3.5 release 签名的条件启用

**结论**：脚本在仓库外 properties 缺失时不创建 release 签名配置并禁用 release 变体；当前 properties 存在，release 变体启用且签名可验证。缺文件分支为**只读脚本判断**，按指令未隐藏/移动文件做动态实验。

**证据**

- `app/build.gradle.kts` L12—19：默认路径 `~/.config/nautile/keystore.properties`，`hasReleaseSigning = isFile && storeFile 非空`。
- L34—43：仅在 `hasReleaseSigning` 时 `create("release")`；L46—51：`release` buildType 仅在条件成立时赋 `signingConfig`。
- L77—82：`androidComponents.beforeVariants` 对 release 设 `variantBuilder.enable = hasReleaseSigning`，即缺文件时不生成 release 变体。
- 当前产物：`app-release.apk` 24,596,328 B；`apksigner verify --print-certs` 输出 `CN=Nautile, OU=Course Project, O=Nautile, C=CN`、SHA-256 `d8e58a2842c85f5dfebe5022578c5818989c88a1d3ee9ea6923341ad8aee2320`（与 debug 证书不同）。
- 路径差异：计划 v2 K4 写 `~/.local/share/nautile-keys/keystore.properties`，实际在 `~/.config/nautile/`；与 `docs/任务进度.md` L158 的记录一致。

**影响**：他人无该文件时可构建 debug 且不会使用错误密钥；release 变体被跳过而不是退回 debug 签名。缺文件行为未做运行验证，仅脚本判断。
