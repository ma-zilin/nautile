### 3.1 高优先级问题（阻断冻结，必须修复）

#### [H-01] 事件颜色归属、DB v5 字段与标签 8 色选择器存在根本性架构冲突
- **冲突点**：
  1. **颜色由谁决定（事件级相邻异色 vs 标签/分类绑定色）**：
     - **需求基线 v2.17**（`docs/需求基线.md:13, 47, 283(FR-S-14), 303(FR-T-03), 317(FR-T-21), 543(AC-S-13), 551(AC-T-20)`）：明确要求引入**事件颜色库**，保证**相邻日程与相邻日志事件不同色**并持久化 `colorIndex`。
     - **架构提案**（`R7_架构提案与迁移边界.md:36-41, 60-65, 264-322`）：DB v4→v5 **仅在 `schedule_events` 与 `time_logs` 新增 `color_index INTEGER`**，**未改 `schedule_tags` 与 `time_categories`**；由 `EventColorRules.pickColorIndex` 在创建/开始计时/补录时动态避让重叠与相邻事件写入 `event.colorIndex` / `log.colorIndex`。
     - **06 规格**（`06_R7统一视觉与交互规格.md:217-218, 341, 398-401, 538, 583`）：写成日程块按 `ScheduleTag.colorIndex` 映射（系统“课程表”固定槽 6、无标签固定槽 0），日志块按父级分类 `colorIndex` 映射；同时在 `TagManagementScreen` / `TagEditSheet` 要求**自定义标签支持 8 色选择**（含 `tag_color_slot_{0..7}` 与“换色立即刷新关联日程色块”）。
     - **后果**：① 与 DB v5 `schedule_tags` 无 `color_index` 列直接冲突（`ScheduleTagCommands` 也无颜色参数）；② 按标签/分类固定着色的设计会导致连续多节课程或连续多条无标签日程/同分类日志呈现相同颜色，**直接违背基线“相邻不同色并持久化事件 `colorIndex`”的强制要求**。
  2. **色槽数据结构与边框宽度不统一**：
     - **06 规格**（`L183, 238-239`）：4 字段 `NautileEventColorSlot(container, border, accent, onContainer)` + `LocalNautileEventColors` + `1dp` 描边 + 左侧 `3dp accent` 竖条。
     - **架构提案**（`L332-347, 362`）：3 字段 `EventColorTokens(container, border, content)` + `EventColorPalette.resolve` + `LocalNautileDarkTheme` + `1.5dp` 描边（无 `accent` 竖条）。
- **必修正动作**：
  - **`frontend-design-lead`（06 规格）**：将 §3.1、§5.1（L341）、§5.5（L398–401）、§9（L538）、§10 G3（L583）对齐至基线与 DB v5——移除 `ScheduleTag.colorIndex` 与 `TagEditSheet` 8 色选择器（标签仅管名称与关联日程数），明确日程块与日志块按**事件/日志自身持久化的 `colorIndex`**（相邻/重叠异色分配，旧行 `null` 确定性回退）消费 8 色槽；如统计饼图按父分类取色则明确以 `floorMod(parentId, 8)` 消费同一 8 色板。
  - **`frontend-design-lead` 与 `architecture-designer` 会签**：统一色槽模型字段（3 字段还是 4 字段含 `accent`）、`CompositionLocal` 命名及边框宽度（`1.dp` vs `1.5.dp`）。
