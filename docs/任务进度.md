## 刚性验证原则（2026-11-21 我定）

**判决只认**：命令退出码、测试结果统计、lint error 数、Room schema diff、构建产物存在性。不以大模型阅读代码或逻辑分析作为验证结论。

**每条结论必须附**：执行的命令、退出码、关键统计、执行时间、git HEAD 与工作区状态（dirty/clean）。

**出现任一情形即退回**：只有文字推断无命令与退出码；测试名不含 AC 编号或拒绝分支未覆盖；只有开发自测、无独立复跑；把未执行/未自动化/真机人工项写成“通过”；依赖 Gradle up-to-date 跳过测试却声称执行过。

**不可自动化项**（真机手势、预测返回动画、锁屏/被杀恢复、系统通知与权限）单列“人工清单”，写明执行条件、实际结果与截图，标“未自动化”，不计入代码验证通过项。

**验证物要求**：
1. 从 AC 写测试（不看实现），测试名带 AC 编号，正常路径与每个拒绝分支各至少一例；先红后绿，报告留红/绿证据；
2. 存储层契约测试：同一组断言同时约束内存替身与 Room 实现（抽象基类共享）；
3. 架构边界测试：JUnit 扫源码，断言 domain 不 import android/androidx、data 不 import ui、ui 不 import data.db；
4. 数据库：MigrationTestHelper＋`app/schemas/1.json` 验证 version 1 可打开；schema 变化须可解释，否则 FAIL；
5. UI 行为：Compose UI test 覆盖 AC 中可在模拟器/真机自动判定的项；
6. 门禁脚本 `scripts/verify.sh <任务号>`：编译→单测→lint→（可选设备测试），任一非 0 即 FAIL；必须 `--rerun-tasks`；记录 HEAD 与 dirty；输出 PASS/FAIL 并归档到 `docs/验证记录/`；
7. 验证不改业务代码；测试或门禁需要改实现时，退回开发并记录原因。

**协调职责**：此后每份任务书必须含 AC 子集、刚性验证清单、门禁命令、证据路径、不可自动化项，缺一不得派发；状态只在门禁 PASS 且证据入库后标“已完成”，FAIL 转“待修复”；独立验证必须复跑，开发自测只作辅助，冲突以可复现命令为准并交我裁决；监督先红后绿，每个里程碑做一次变异抽查（注入 bug 验证测试变红，记录后还原）；新增依赖（ktlint/detekt/Kover/CI 等）先报我批准。

**角色边界（2026-11-21 我纠正）**：从 AC 写测试、契约/边界/迁移测试、门禁脚本、独立复跑、红绿证据与变异抽查，一律由独立验证 Agent 负责；开发 Agent 只交付实现与辅助自测，不写判决性测试、不宣称通过。开发任务书里只写 AC 子集（范围）、自测输出要求、证据路径与不可自动化项，不把验证裁决物派给开发。

**当前影响**：S1-T01—T-05 此前是“开发自测＋协调抽查”，未过门禁，状态改为“已实现，待刚性验证”；T-06/T-07 已开工，开发任务书只补 AC 子集（范围）、自测输出要求、证据路径与不可自动化项；验证裁决物由 T-051/T-052 承担。
